# Contract: GraphQL Conventions

**Version**: 1.0.0

## Overview

GraphQL schemas generated by the gateway follow these conventions
to ensure domain-oriented, consistent, and predictable APIs.

## Naming Conventions

| Concept      | Convention                  | Example                              |
| ------------ | --------------------------- | ------------------------------------ |
| Query fields | camelCase, domain-oriented  | `marketSnapshot`, `tradeOpportunity` |
| Types        | PascalCase, domain nouns    | `MarketSnapshot`, `EveType`          |
| Input types  | PascalCase + "Input" suffix | `TradeOpportunityInput`              |
| Enum types   | PascalCase                  | `DataSource`                         |
| Enum values  | SCREAMING_SNAKE_CASE        | `ESI`, `SDE`, `DERIVED`              |
| Scalar types | PascalCase, semantic names  | `ISK`, `TypeReference`               |
| Field names  | camelCase                   | `lowestSell`, `highestBuy`           |

## Schema Structure

Generated schemas follow this pattern:

```graphql
# Custom scalars from semantic types
scalar ISK
scalar TypeReference
scalar RegionReference

# Domain types from pipeline outputs
type MarketSnapshot {
  item: EveType!
  lowestSell: ISK!
  highestBuy: ISK!
}

# Input types from pipeline inputs
input MarketSnapshotInput {
  item: TypeReference!
  region: RegionReference!
}

# Query fields from published schemas
type Query {
  marketSnapshot(input: MarketSnapshotInput!): MarketSnapshot!
}
```

## Provenance Exposure

Provenance is optionally available via a `_provenance` field:

```graphql
type DataProvenance {
  source: DataSource!
  capability: String!
  version: Int!
  retrievedAt: DateTime
  calculatedAt: DateTime
  cached: Boolean!
}

enum DataSource {
  ESI
  SDE
  DERIVED
  CACHE
}
```

Provenance fields are opt-in. They appear only when requested
in the selection set and do not add execution cost when omitted.

## Error Responses

Errors follow the GraphQL spec `errors` array format with
structured `extensions`:

```json
{
  "errors": [
    {
      "message": "Source unavailable: ESI market endpoint",
      "extensions": {
        "code": "SOURCE_UNAVAILABLE",
        "category": "runtime",
        "capability": "market.orders",
        "source": "ESI"
      }
    }
  ]
}
```

Raw infrastructure details (stack traces, internal URLs, connection
strings) MUST NOT appear in error responses.

## Selection-Set Optimization

The gateway uses the GraphQL selection set to prune the execution
plan. Fields not requested in the query do not trigger their
associated capability execution.

Example: querying only `{ item { name } }` on a schema that also
provides market data will NOT invoke ESI market capabilities.

## Nullability Rules

| Scenario                                   | Convention                                   |
| ------------------------------------------ | -------------------------------------------- |
| Field always available from source         | Non-null (`!`)                               |
| Field requires specific auth scope         | Nullable (may be null if scope unavailable)  |
| Field from optional pipeline output        | Nullable                                     |
| List fields                                | Non-null list of non-null items (`[Type!]!`) |
| Input fields from required pipeline inputs | Non-null (`!`)                               |
| Input fields from optional pipeline inputs | Nullable                                     |
